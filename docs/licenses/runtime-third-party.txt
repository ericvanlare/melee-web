WebMelee runtime third-party notices
=================================

Audit date: September 12, 2026

This file contains verbatim notice and license text copied from the pinned local
sources used to configure the browser-release build, together with the existing
notices for source adaptations that are part of the runtime. It is a conservative
configured-dependency inventory: it intentionally errs on inclusion and is not an
exact post-link or post-dead-code-elimination SBOM. Dependencies that are absent
from the configured source trees are not listed; some configured targets and
optional notices are included conservatively even when feature flags or
link-time elimination omit their code.

The aggregate delivers license and attribution text. It does not deliver
corresponding source, establish a distribution right for recovered Melee/HSD or
original platform code, clear the generated Aurora pipeline seed, or make a
relicensing statement. Those questions remain release-review items.

Browser build basis
-------------------

* Project runtime and bridges are built in the Release `gameplay_public` target.
* Aurora: `encounter/aurora` commit
  `749d6ee7a22bdfab78c8ece9047bca5d79aa72ca`
  (<https://github.com/encounter/aurora/tree/749d6ee7a22bdfab78c8ece9047bca5d79aa72ca>).
* Emscripten: emsdk commit `5eb0bde7585670252e8ba05e9d361627bffd08b5`,
  Emscripten `6.0.9`, compiler revision
  `4e4223852a0835923411059a3929907d7df1232e`,
  (<https://github.com/emscripten-core/emsdk/tree/5eb0bde7585670252e8ba05e9d361627bffd08b5>).
* WebGPU: the browser build uses Aurora's Emscripten provider and the
  `emdawnwebgpu` port, package `v20260423.175430`, Dawn revision
  `31e25af254ab572c77054edec4946d2244e184dd`
  (<https://dawn.googlesource.com/dawn/+log/31e25af254ab572c77054edec4946d2244e184dd>).
* The generated browser backend adapts the pinned Dear ImGui WebGPU backend for
  the modern Emdawn ABI by changing its Emscripten guard and value-initializing
  `WGPUVertexBufferLayout`; the source adaptation is generated by
  `.deps/aurora/extern/CMakeLists.txt`.
* The Aurora build applies its configured zlib-ng compatibility patch. The
  configured SDL archive includes Aurora's patch hooks; the browser-specific
  Emscripten build does not turn on Aurora's Android-only SDL changes.

The recovered Melee/HSD tree, original AX/AXFX platform units and generated
pipeline seed are described in `docs/licenses/PLAYABLE_RUNTIME_NOTICES.md` and
are intentionally not represented as permissively licensed components here.
