# UCF input-history lifetime and rollback ownership

**Source identified / Reference compiled / Selected initialization metadata observed / Isolated storage validated**

[Milestone #339](https://github.com/ericvanlare/melee-web/issues/339) binds the
shared UCF Pad Buffer/Cardinals history before its dependent behaviors are
implemented. The source describes four 12-byte rows with 40 meaningful bytes,
indexed by the processed PAD slot. Selected endpoint observations identify a
candidate runtime table span. A standalone format-v1 storage component now
passes independent review and the full repository suite, but it is not wired
to a live producer, consumer, match reset, or Slippi snapshot path. Actual
nonzero history updates, match lifetime and dynamic capture/restore behavior
remain open. The [structured receipt](../evidence/ucf-history-ownership-v1.json)
keeps exact source, failure, review and build identities.

## Offline initialization boundary

Two bounded init-only attempts used the new reference artifact and private
profiles under a default-deny policy with only the exact local Unix observer
endpoint. No official Slippi services were contacted. The first stopped after
4.439 seconds: the future pointer slot still contained original-game exception
table data, so the strict decoder correctly refused it as a GCT pointer.
Source/disc reduction identified that exact startup state; repeated chain values
were invalid intermediates, not payload reads. Independent review and focused
controls passed before the minimal observer adapter was integrated.

The second attempt retained that exact initial snapshot and continued under the
unchanged 45-second observation limit. It received heap-word readings,
but never received an installed pointer or changed hook. It stopped at the
deadline, taking 46.807 seconds including preflight and cleanup. No UCF table,
reset, snapshot membership or rollback behavior was established. Diagnostic
word changes are not promoted to game-progress evidence. Endpoint senders are
not authenticated; the receipt keeps that limitation explicit.

Both failed profiles and raw observations are preserved. Each owned process
group was verified absent and its observer socket removed. The adapter passed
17 pure integration controls and independent review; its strict postinstall
decoder and timeout/cleanup budgets remain unchanged.

## Reduced conversion dependency

The two-attempt stopping rule led to a source-only reduction. The retained
private profile contains an empty game-ID entry from a Running-state statistics
sample. Normal teardown resets the ID to a different literal after joining that
thread, so teardown alone does not explain the empty entry. If that ID was also
empty during patch selection, source logic would select no game INIs and skip
the installer. The actual boot-time ID and active patch vector were not observed;
this is a source-supported lead, not proof of the cause.

A tiny independent fixture then tested the same standard CP1252-to-UTF-8 API
with fixed `GALE01` bytes under the relevant system-resource restrictions.
Compilation passed; `iconv_open` failed with errno 22 before consuming input.
Both owned fixture process groups were verified absent. This isolates a host
conversion failure, but does not identify a denied resource or prove that it
caused the client's empty ID. The fixture reads no game/disc data and permits
no network access.

Pinned Apple reference source and installed mapping tables identified a candidate
set of six system data files. With only read access to those exact files added,
the same compiled fixture converted the six-byte `GALE01` input exactly; its owned process
group was verified absent. The baseline failure remains retained. This supports
the fixture's conversion dependency; the Apple source revision is not asserted
to be the exact installed system implementation, and the client cause remains
unobserved.

## Selected initialization metadata

A separately reviewed third attempt used a fresh private profile and those six
exact file-read grants. The executable, resources, strict decoder, network denial
and observation/cleanup limits remained unchanged. It reached selected metadata
in 3.640 seconds. Independent replay of all three retained datagrams exactly
reproduces the saved decoder report; all 17 retained files match their hashes.
The owned process group and observer socket are absent.

The first valid pointer observation is `0x8065cc80`; the observed hook targets
payload `0x8065d4d8`.
Its authored table span is `[0x8065d4dc, 0x8065d50c)`: 48 bytes containing four
12-byte rows and 40 meaningful bytes. The expected header and instruction
fingerprints agree. Twelve sampled words in that one snapshot are zero; this
does not establish a reset rule or history behavior.

These are unauthenticated endpoint observations while the owned launcher was
alive. Target execution is not independently confirmed, and the delta stream
has no source sequence proving atomic or loss-free state. This is selected
initialization metadata, not a gameplay or rollback witness. The six grants
were supported as a group by the conversion fixture; neither their individual
necessity nor the client's original failure cause was proved.

## Isolated history storage component

Source commit `11c24f87a266c237b1a4c53edceae6f2962fdd5f` adds the standalone
GPL own-C `ucf_input_history` component at storage format version 1. Its payload
is exactly four 12-byte rows (48 bytes total), including all eight reserved
bytes. Fresh ownership uses a caller-provided unique nonzero token; snapshots
copy payload bytes and fieldwise format/token metadata, and disposal invalidates
the token. The existing active identity remains
`slippi-render-dependencies-dbooc-shield-drop-v5`; this component is unreferenced
by the overlay and adds no live history producer or consumer, per-match reset,
or runtime snapshot integration.

Independent code review passed for the seven component, fixture, discovery and
README files. The focused native/Wasm fixture passed and emitted the same
captured 48-byte vector in both environments. A retained disposable
copy-before-refusal mutant failed the fixture's unchanged-state assertion as
expected. The full regression at this source commit exited successfully after
unittest reported 2,427 tests, with 166 skipped, in 530.218 seconds (530.759
seconds runner elapsed). These controls validate only the isolated storage API;
they do not demonstrate a real UCF history update, live reset, or game
Capture/Load behavior. Exact file and receipt hashes are in the structured
receipt.

## Next boundary

Pinned source places the entire observed 48-byte span inside the fixed backup
region `[0x8065c000, 0x8071b000)`, with no overlap among 30 active exclusions.
It lies below the observed main heap; fixed-region membership is the ownership
basis. This static projection does not establish that Capture/Load ran, or that
guest preserve blocks did not overwrite restored bytes.

The next engineering step is preparation of the minimal phase and ordinary-input
bridge under the reviewed source plan; no runtime route or attempt has been
released. The first proposed observation is a local chooser input and phase
change, without confirming a mode. A later eligible human-fighter observation
will seek nonzero history under a valid installed-pointer epoch. The five
still-open consumer paths, actual match/reset lifetime, and Slippi Capture/Load
preserve-block and restore-order behavior remain separate gates. The isolated component
does not establish those runtime behaviors. Do not repeat successful
initialization without a new hypothesis. No complete profile or live rollback
claim follows.
