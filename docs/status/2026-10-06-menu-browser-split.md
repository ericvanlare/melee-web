# Native menu browser runtime split by scene

**Compiled / Source identified / Browser exercised (original CSS observer capture and smoke)** for a behavior-preserving restructure of `src/gameplay_menu_browser.cpp`, the repository's worst merge-conflict file (architects' log ask A1). No gameplay, timing, input, audio or accuracy claim is made or changed. The [scoped receipt](../evidence/menu-browser-split-v1.json) binds the comparisons below.

## File map

| Unit | Owns |
| --- | --- |
| `src/gameplay_menu_browser.cpp` | Shared state definitions (original order), scene routing, `tick()`, scene entry and transitions, session lifecycle exports and `main()` |
| `src/gameplay_menu_browser_state.hpp` | Internal header that shares that state; the former anonymous namespace is `melee_web_menu_browser`, with a using-directive in each unit so unqualified lookup is unchanged |
| `src/gameplay_menu_browser_menu.cpp` | Disc import and upload allowlists, streamed source files, save profile, menu prepare/launch, CSS/SSS drivers |
| `src/gameplay_menu_browser_match.cpp` | Reference replay, source player state, stock check |
| `src/gameplay_menu_browser_results.cpp` | Results PAD and pause schedules |
| `src/gameplay_menu_browser_diagnostics.cpp` | Start confirmation, raw PAD samples, diagnostics line |
| `src/gameplay_menu_browser_observers.cpp` | Every JSON observer and serializer |
| `src/fixed_format_writer.hpp` | `FixedFormatWriter`: one `add()` call per JSON field |

To add an observer field, insert one `out.add(",\"name\":%d",value);` line at the field's position in `gameplay_menu_browser_observers.cpp`. A sequence of `add()` calls writes the same bytes and returns the same length as one `snprintf` over the concatenated format, including truncation (`tests/test_fixed_format_writer.py` checks every buffer size). Source-shape tests read the joined units through `tests/menu_browser_source.py`, which fails if a unit is added without updating its list.

## What was compared

### Historical comparison (baseline `07bcfdf`)

The following interface, function, serializer, and observer details retain the earlier comparison against main at `07bcfdf`. They are historical evidence and do not replace the current-base revalidation below. Both sides used the same toolchain and flags.

- **Wasm interface.** The RelWithDebInfo `runtime` build has identical export and import entries (239 exports, 398 imports by name, kind and signature; section order differs with object-file order). Release `runtime`, `runtime-public` and `runtime-audio-preview` minify names, so their historical comparison maps symbols through the JS names bound by the glue and checks Wasm kinds and signatures. The compared native API entries match. Emscripten's generated invoke trampoline pair differs: `dynCall_vidddiii` / `invoke_vidddiii` before the split and `dynCall_vidddii` / `invoke_vidddii` after it; these generated helpers are not native API exports.
- **Cause of that pair.** The helper is generated from the Wasm signature of `report_construction(const char*, double, double, double, const AuroraStats&, const AuroraStats&)`. In the baseline it had internal linkage, so the optimizer promoted the `before` reference into two scalar arguments and the function took seven parameters. The split must share it with the menu unit, so it has external linkage and keeps its declared six parameters; the matching helper pair is generated for that signature. The glue binds each build's pair consistently, and `scene-prepare` (the call site that uses it) reported through `window.menuConstructionTiming` in the Release capture. It is a generated helper ABI difference; the native API contract did not change.
- **Functions.** The Release development build has 15,490 functions before and 15,476 after. With the anonymous namespace and numeric suffixes normalized, 29 names exist only before and 15 only after: shared helpers that are now external and stay out of line (`begin_preparation`, `begin_source_session`, `finish_asset_handoff`, `PreparationProfile::report`, `FixedFormatWriter::add` and similar), small host accessors, inline session methods and `make_unique` instantiations that the optimizer now inlines, a renumbered lambda, renumbered global-destructor stubs, and the trampoline pair above. The source call counts of the 13 free functions that left the list (`melee_web_menu_host_*` and similar) are unchanged.
- **EM_ASM bodies.** Identical for RelWithDebInfo (120) and the Release development build (120). The public and audio-preview Release glue lose one dead string, `window.menuPreparation?.(UTF8ToString($0))` from the replay export, which those builds forbid; the baseline's public Wasm contains no code that references it. The likely cause, not isolated, is that the string section of the new match unit is no longer retained once nothing in it is referenced.
- **Observer format.** For each of the 11 converted `snprintf` calls, the buffer, the concatenated format and the ordered argument list equal the original, with `TARGET_PC` both defined and undefined. With the writer test this establishes byte-identical text for every input, including truncation. Evaluation order is unchanged because the only side effect among the arguments is `++render_frame`, which is still evaluated once at the same point.
- **Observer capture.** Headless Chrome 154 at original CSS with the owned disc: `source_observe` (618 bytes, populated), `match_observe`, `results_pad_trace`, `results_entry_packet`, `diagnostics` and `phase` are exact-text equal before and after, both before and after unload, for RelWithDebInfo and Release development builds. The runtime timing hook (216 to 218 payloads) has one identical key order and set of key and number types in every payload, and the construction hook reports the same kinds in the same order (`scene-prepare`, `scene-enter`, `lifecycle-close`). Wall-clock values are not compared. In `memory`, only `allocator_*` fields differ (live and free malloc statistics also change between two runs of the same build; `allocator_arena_bytes`, and in RelWithDebInfo `allocator_top_free_bytes`, differ between builds by amounts whose cause was not isolated); `wasm_heap_bytes` and every `source_*` field are equal.

## Tests and builds

- The required split builds passed for `runtime` RelWithDebInfo, `runtime` Release, `runtime-public` Release, and `runtime-audio-preview` Release, with no compiler warnings from the new units (Release warnings came from pinned SDK headers). The `verify (menus)` partition passed, and the full suite passed 1,900 tests with 139 skips (owned DOL, fighter archives and similar local inputs are absent in this checkout).
- Paired current-base headless captures reached original CSS and tore down cleanly in RelWithDebInfo and Release; observer evidence is scoped above.
- The `MELEE_WEB_PIPELINE_PROVENANCE` and `MELEE_WEB_SELECTIVE_PIPELINES` variants were not built.

## Not claimed

No timing, performance, pixel, PCM, physical-input or retail-comparison claim. Host-native microbenchmark of the per-field writer against one packed `snprintf` (about 55 doubles and 8 integers) was within 4% (about 0.2 microseconds per call); it is indicative only and not a Wasm measurement. The writer applies to development timing JSON at the callback rate, and to non-hot diagnostics elsewhere.

## Follow-ups noticed, not changed

- `src/gameplay_menu_browser.cpp` still holds 1,715 lines: `tick()`, scene entry and transitions share many inlined helpers, and splitting them can change inlining. It is the next candidate.
- The allowlist arrays in `gameplay_menu_browser_menu.cpp` carry their element count in the type (`std::array<std::string_view,379>`), so adding a file name still edits two places.
