Privacy Notice

Updated October 1, 2026. Work in progress.

This notice describes the current public player prototype and the information handled when you visit or use it.

What the player handles

The player loads its HTML, stylesheet, JavaScript modules and same-origin WebAssembly/data files. When you choose a supported ISO, GCM or CISO, bounded reads validate the local disc structure and expected USA 1.02 executable, then copy only the required game data into page-local native memory. The selected file, its operating-system filename, the executable hash, archive names and derived data are handled locally by the current source path.

The current public source path has no application account, analytics or advertising. Automatic technical diagnostics are described below. It does not send the selected file, filename, executable hash or derived game data to the operator. Gamepad information is read locally to map controller input and show connected controller descriptions. Optional controller recordings are prepared locally for you to download; they are not uploaded. These statements describe the reviewed source path; deployment verification should confirm the same request and module inventory.

Storage on your device

The player stores keyboard layout, per-player input source, and optional touch-overlay opacity preferences in localStorage under melee-prototype-keyboard-v1. Custom controller mappings are stored under melee-controller-profiles-v1, keyed by browser family, platform, controller description and reported input layout. Raw input recordings are held in memory only when you start recording and can be downloaded to your device. If browser storage is unavailable, controls work for the session.

To investigate interruptions, the player keeps a small recent history of timing, source-frame and selected scene/character/stage identifiers, graphics preparation counters, audio-buffer health and page lifecycle observations. An interruption can freeze that history into a local diagnostic record. These records exclude disc data and filenames, save contents, player names, controller inputs, full URLs, exception text and memory contents. They use temporary session identifiers and coarse browser/platform information. At most four records and 256 KiB are retained in the separate melee-web-runtime-diagnostics IndexedDB database; older records are evicted. Storage failures do not prevent playing or write into Personal progress. Local retention and export continue when automatic reporting is off. Clearing this site's browser data removes local diagnostics along with other site storage. A browser or process crash can prevent a record from being captured or saved.

On known WebMelee staging and production addresses, automatic diagnostics are enabled by default. The player sends a bounded technical report to the same-origin /api/diagnostics endpoint while gameplay is inactive. Local development and unknown preview addresses retain reports locally. In Settings, turn off Automatic diagnostics to stop future delivery and remove unsent upload work, or choose Export diagnostics to download local records while gameplay is paused. The reporting preference is stored separately from Personal progress; if browser storage is denied, turning reporting off still applies for the current visit.

Delivery is best effort: the separate melee-web-diagnostics-delivery database holds at most four pending reports and 256 KiB for up to seven days. Reports are capped at 64 KiB, with bounded retries and at most four upload attempts per visit. Upload requests omit cookies and credentials. Turning reporting off cannot retract a request that the server already received. Reports include source/build identity, the site origin without a path or query, temporary incident identifiers, coarse browser/platform information and allowlisted technical observations. They exclude your disc data and filenames, saves, player names, controller histories, credentials, full URLs, arbitrary exception strings and raw memory. Playing never depends on diagnostics being stored or delivered.

The operator uses reports to investigate interruptions. Staging and production records are separated. Developer retrieval requires authentication; no public report list or download is provided. Reports expire from retrieval after 30 days. Scheduled bounded deletion removes expired rows, normally within the next maintenance window; provider or maintenance outages can delay physical deletion. Cloudflare also receives ordinary network request information when a report is delivered, as described below.

Save settings and Personal progress are stored locally in this browser's IndexedDB database webmelee-save-profiles-v1. Personal progress contains the supported original game-card save fields; it does not include temporary match state. The database keeps checksummed versions for local recovery. WebMelee requests persistent browser storage when available, but the browser can deny that request or later clear site data. The save is tied to this browser profile and site origin; it is not uploaded or synchronized. Use Export save to download a GameCube .gci backup and Load save file to read one. Those actions handle the file locally. If browser storage is unavailable, the player reports the save error rather than silently storing progress elsewhere.

The public loader does not use cookies, sessionStorage, Cache Storage or a service worker. The native renderer may create a page-local pipeline database in its in-memory filesystem; the public loader does not mount IDBFS or persist that database through its cache module. Eject first asks Personal progress to commit a final snapshot, then unloads the native scene and reloads the page. That full reload retires the page and WebAssembly heaps, imported archive bytes and decoded assets. It does not clear save profiles, keyboard or controller preferences, ordinary browser HTTP cache or history, or a graphics-driver cache. The player cannot control those browser and driver caches.

Hosting and network requests

Cloudflare Pages serves the site. Visiting a page necessarily sends network information such as your IP address, requested URL and browser request headers to the hosting provider. The provider may process request, security and operational information to deliver and protect the service. We do not set the provider's operational retention periods, and the limited application reports described above do not limit the provider’s own operational processing.

Cloudflare describes its practices in its Privacy Policy. The player requests its own same-origin resources; do not put personal information in URLs or choose a disc image for any feature other than the local player. Links to other sites are governed by those sites' practices.

If you contact us

Email goes to the operator and the mail providers involved in delivery. We use your message, sender address and attachments to respond, investigate a reported problem or address a rights claim. We retain correspondence only as needed for those purposes and applicable legal obligations. Do not attach disc images, extracted game data, credentials or unrelated personal information.
